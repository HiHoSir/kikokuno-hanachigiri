# 制作手順（作品非依存）

## 1. 入力の承認・管理
- 対象物の正しい原画、方向ID、立ちポーズ、透過背景、制作権限を確認する。
- 各原画の元ファイルSHA256を保存。元ファイルを再保存してハッシュが変わらないよう保管する。
- 原画がアニメーションの一コマなら、そのコマを基準にする。別方向のポーズを勝手に再生成しない。
- サイズ、余白、足元（またはオブジェクトの接地面）、共通パレット、保護したい領域を作品設定へ記録。

## 2. 黒塗りシルエット → Nearest
- `alpha >= threshold` で対象の二値マスクを作る。
- BBoxを計算し、`min((W-2*margin_x)/bbox_w, (H-margin_top-margin_bottom)/bbox_h)` で縮尺を決める。
- マスク**だけ**に最近傍補間を使用。出力キャンバス中央／足元余白に配置する。真横や斜め方向で見かけ幅が異なるのは構わない。
- 周辺グローや背景も含む場合はこの段階で停止。マスクを修正して再生成する。
- `draft-...-mask.png` の輪郭が原画と一致するまでカラー工程へ進まない。

## 3. 配色ガイドと色面設計
- 原画の色分布を **BOX面積平均**して参考色ガイドを得る。これは最終ドットを減色するだけの手法ではない。
- 作品固有の色パレットを用意し、髪・肌・服・靴・装備などの**意味上の区分**を整理。色カテゴリはキャラクターやNPCで変わる。
- 自動色近似で得た初期画像はラフ。塗りつぶしの位置、目、袖、装飾などは人間/AIが意図を持って打ち直す。
- 境界や模様の細部は1px幅にこだわらず、実寸で識別できる形にデフォルメしてよい。ただし形状変更・alpha変更は別案とする。

## 4. 意味を持つ実ドット修正
1. 現在のPNGを保存してからコピー。
2. 一度に1部位（髪の束、目、腕、衣装面など）だけ扱う。
3. 通常は輪郭(alpha)、方向、手足の向き、接地位置、ユーザーが固定した特徴を保護。丸い部位の角が直角に見える場合は [任意の1px角落とし](CORNER_TRIMMING.md) を別候補・別パッチで行い、その後の色修正では再びalphaを固定する。
   - ジグザグ陰影を比較する場合は [専用手順](ZIGZAG_SHADING.md) を使い、通常版と同じalpha・パレット・接地点の別候補にする。
4. `x,y` (0始まり) の変更前 RGBA と修正後 RGBA をログ化。
5. `make-patch`、`apply` で最初のPNGから完全一致することを確認。
6. 実寸と2x/4x/6x Nearest拡大の両方で原画・修正前・修正後を比較。
7. 機械検査合格だけで美術採用とはしない。

## 5. 納品物
- 元の承認画像（無変更）、シルエット、RGBA PNG、差分パッチ、色パレット、検査ログ、比較画像。
- 複数方向は `views.json` の各方向ファイルを独立で管理。方向数やアトラスサイズは作品設定に従う。
- 未制作方向・歩行コマは「未制作」と明記し、空のままにする。
