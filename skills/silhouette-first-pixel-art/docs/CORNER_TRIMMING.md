# 丸い部位の1px角落とし（任意工程）

## 使う場面

髪の外形・頬・肩・丸い小物など、本来丸い部位に `┏ / ┓ / ┗ / ┛` の直角が目立つときに使う。外側の角にある1ドットを落とし、横と縦の輪郭を斜めにつなげる。ぼかしや半透明化ではなく、選んだ画素を削るピクセル作画として扱う。

「丸い部位」という意味付けを先に行う。同じ形の画素配置でも、曲線と四角い部品では処理を変える。全体への角削除フィルター、輪郭の収縮、繰り返し削除は行わない。

## 対象と保護

| 対象 | 扱い |
| --- | --- |
| 外周の凸角 | 丸く見せたい箇所だけ候補にする。外側へ突き出た角1pxを選ぶ |
| 既に滑らかな斜め輪郭・階段状の線 | 段差ごとの角を削らない。意図した1:1、2:1等のドットの並びを保つ |
| 髪束の先端・角・指先・リボン・武器・四角い部品 | 尖りや構造を表すため保護する。角という名称だけで丸めない |
| 1px幅の細線・くびれ・手足の接続部 | 削除による切断を避けるため保護する |
| 眼・口・花飾り等の識別要素、靴底・接地面 | 作品別の保護領域に登録する |
| 色面内部の角 | 透明な穴を開けず、接する材質のパレット色で置き換える。alphaは固定 |

外周候補は、横と縦に不透明画素が続き、外側が透明である凸角から選ぶ。斜め内側にも面があるかを確認する。1pxのL字線は、同じ角配置でも細線として保護する。判定は局所パターンだけで完結せず、原画と部位の意味を目視して決める。

## 実施手順

1. 通常の色面・1px修正ができた画像を `before.png` として保存し、元の採用画像を残す。原画・方向・カメラ・寸法・足元アンカー・倍率を引き継ぐ。
2. 実寸と4x/6x Nearestで外形を比較し、削りたい角を座標で列挙する。たとえば `[(12,8)]` のように対象を事前確定する。座標は例であり、別画像へコピーしない。
3. 専用部位 `corner_trim` の `editable_parts` に、選んだ画素ごとの1×1矩形 `[x,y,x+1,y+1]` を登録する。顔・角・毛先・装飾・手・接地面の `protected` は維持する。髪全体の広い編集ガードでalpha制限を解除しない。
4. 別候補 `corner_candidate.png` にだけ、選んだ不透明画素をRGBA `[0,0,0,0]` にする。1回目は1つの角につき1pxまで。周辺の画素や透明RGBを変更しない。色面内部の角修正はこの削除パッチと分け、通常のalpha固定パッチで行う。
5. 以下で差分を記録し、座標限定ガード付きで再適用する。`corner_guard.json` には今回の実座標を登録する。

```bash
python scripts/pixel_pipeline.py inspect before.png corner_candidate.png --protect-bottom 16
python scripts/pixel_pipeline.py make-patch before.png corner_candidate.png corner_patch.json --view front_right --part corner_trim
python scripts/pixel_pipeline.py apply before.png corner_patch.json corner_replayed.png --allow-alpha-change --guard corner_guard.json --view front_right --part corner_trim
```

上の方向IDと最下16行は例。実素材の方向・保護行に置き換える。**通常の色修正では `--allow-alpha-change` を付けない。** `guard-check` は既定でalpha変更を拒否するため、外周削除の可否をその既定コマンドだけで判定しない。

6. パッチの変更座標集合が事前リストと完全一致し、全変更が不透明 `255→0` かつ変更後RGBA `[0,0,0,0]` であることを確認する。`inspect` のRGBA変更数・alpha変更数が削除座標数と一致し、その他の画素・保護領域の差分が0であることも確認する。ガード付き再適用の成功と、候補PNG・再適用PNGの全RGBA一致を照合する。
7. 実寸・整数倍・同じ背景で比較する。穴、孤立ドット、線の切断、毛束や装飾の欠けを確認する。削除で隣の明るい画素が外周へ露出し、輪郭が欠けて見える場合は、別のalpha固定・部位限定パッチで輪郭色を補修する。寸法、位置、足元アンカーを変えずに比較し、通常の色修正へ戻ったらalphaを再固定する。
8. アニメーションは共通尺度・共通アンカーを維持し、部位の形をフレーム間で照合する。全フレームへ同一座標をコピーせず、再生時のちらつきを確認する。静止1枚だけの確認をアニメ合格にしない。

## 記録と限界

- 元画像のSHA、対象部位、方向・フレーム、削除座標、前後RGBA、差分パッチ、再適用一致、目視比較、採用状態を残す。
- この工程を行う許可と、本編アセットの差し替え承認は別。元版と別候補を併存させ、採用指示を確認する。
- 既存CLIはSHA・画素・ガードを検査できるが、「丸い部位か」「削ってよい角か」「削除だけか」「切断がないか」は自動保証しない。対象リストと実差分の照合・目視確認は呼び出し側で行う。
