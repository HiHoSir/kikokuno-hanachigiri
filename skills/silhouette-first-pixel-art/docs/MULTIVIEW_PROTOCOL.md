# 複数方向・共通材質の検査プロトコル (v2.1)

## 重要な考え方
「方向間の共通色が増えれば品質が上がる」は誤り。方向で光源、可視部分、面積、陰影が異なるため、共通色数は**診断指標**に留める。髪/肌/布/装飾など*意味のある材質ごと*に整合性を評価する。

`semantic_quality.py audit` の入力は `generic-pixel-multiview-v1` のJSON。以下を各方向で宣言する。

- `id`、`file`：方向・コマの識別と透明PNGの相対パス。方向数は任意。
- `parts`：AI/人間が**確認して付けた領域**。領域の矩形 `rect:[x0,y0,x1,y1]` は右・下端を含まない。`polygon:[[x,y],...]` または `mask` はPNGの非透明領域。
- `materials`：材質IDごとの許容パレット（任意）。`enforce_palette` を真にした場合**だけ**未知の色をエラーとする。
- `landmarks`：照合したい部位の画素座標（例：靴底、肩の高さ）。`landmark_y` は指定方向のy座標の最大差と許容値だけを照合する。
- `features`：装飾や部位の「見えている/隠れている/ない」の**人間/AIによる観察記録**。画像から自動認識した結果ではない。
- `checks`：実際にチェックしたい制約。`feature_visibility` または `feature_count` で明示的な宣言と注釈が一致することだけを検証する。

チェック対象に関する情報が入力にない場合は、勝手に埋めず、`unannotated_feature` や `missing_landmark` を出す。

**方向が異なるPNGの頭身や足元を調べる場合**は、足が接地しているピクセルを見てポイントを手動で登録する。RGBA最下部と靴底は必ずしも同じとは限らない。足元が揃っていてもポーズや関節・手の向きが正しいとは判断できない。

## 使い方

```bash
python scripts/semantic_quality.py audit examples/multiview-example.json --output ./work/multiview-report.json
```

`pass` は宣言された形式的制約の検査合格。アートの品質保証ではない。共通色数・材質ごとの「共通色/総色」・各ビューの色数と使用画素数をレポートに記録する。

## 手・腕・装飾の方向間整合性

1. 参照原画で手首・肘・肩を対応付ける。
2. 正面で手の甲が見えているなら、背面でどの面が見えるか**身体座標と回転角**から確認する。
3. 服や腕の前後の重なり順を目で確認し、保護領域にマーキングする。
4. 矛盾があれば描き込みへ入る前に原画/ポーズを再確認する。
5. 数値テストを通っても、形とポーズの判断に人間の承認が必要。

構造上の矛盾を「少し色を変えるだけ」で解決したことにしない。
