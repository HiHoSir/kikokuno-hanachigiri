# 刀攻撃 v44 — ゲーム用スプライトのサイズ・方向の不具合修正

## 修正理由（2026-11-05）

利用者のiPhone実機確認で、2026-11-05に反映したv44の刀攻撃スプライトについて、**従来キャラクターとサイズが異なり、方向の割り当ても逆**と判明。元v44アニメーションは承認状態を維持するが、旧レンダリング結果 `attack_katana_v44_8dir.png` はランタイム不採用。

## 根本原因

1. 元のレンダラーは右向きのカメラをモデルの+X側（yaw +90°）に置いていた。モデルの前方+Zはその視点でスクリーン左に投影されるため、表示上は左右が反転していた。方向ラベルだけを正しく付けても内容は逆になる。
2. `WORLD_PPM=70` という独自の表示倍率で出力した。既存の承認済み通常姿勢の可視高さ約108pxに対し、GLBから描画した待機姿勢が126pxとなり、刀攻撃だけ約17%大きく見えていた。
3. PNG内に64セルがあり、セル端の欠けがないという検査だけでゲームに組み込んだため、方向とサイズの相互検査をしなかった。

## 修正内容

- 修正スプライト：`attack_katana_v44_corrected_8dir.png`（バージョン付き新規名・キャッシュ衝突防止）。
- 左右方向のカメラyawを反転。8行の向き順は、`front` 0° / `front_right` −45° / `right` −90° / `back_right` −135° / `back` 180° / `back_left` 135° / `left` 90° / `front_left` 45°。
- 原GLBから `WORLD_PPM=60` で再描画。GLBの `V35_Idle` の `front_right` を同じレンダラーで描画した可視高さ **108px** で較正。これは承認済み`normal.png`の可視高さ108pxと一致する。
- 全セルの描画はモデル原点固定、画像内の一律登録オフセット（−2px, −4px）で既存の足元基準へ位置合わせ。フレームごとの移動・トリミングはしていない。
- 従来のランタイムアンカー `[111.6993006993007,209.5212972972973]` と表示倍率 `0.85` は保持。セルは224×256の透明余白を含む共通サイズ、8方向×8フレーム、1.10秒を維持。
- 旧 `attack_katana_8dir.png` と不具合版 `attack_katana_v44_8dir.png` を改変せず、採用GLBと他の8動作はすべて変更なし。

## 自動検査

`tests/attack-atlas-v44.test.js` でカメラ方位（右向きが画面右を向くこと、左向きが左を向くこと）、起点の高さ108px、全64セル非空・クリップなし、GLB基準60px/m、共通アンカー、SHA256画像一致を検査する。これまでの一般的なアトラス検査に加え、方向・サイズの回帰検査を実施する。

## 出力と検証境界

- `tools/hizuki-attack-v44/atlas_qa_corrected.json` が各セルの外接矩形とハッシュ・向きの根拠。
- `assets/characters/hizuki/v35-expanded-cells/attack_katana_v44_corrected_8dir.png` がゲームへの反映物。
