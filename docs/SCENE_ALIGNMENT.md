# 景物の縮尺・接地・遮蔽の修正（06）

05の実機フィードバックを受けた修正。緋月倍率0.85、画像・体型・全モーションの共通アンカー、カメラ、速度・周期距離は維持。背景内で家だけを縮める方式では、小物の大きさと判定のズレを解消できていなかった。

## 共通の物差し

基準は実キャラの後ろ向き仮停止姿勢98px×0.85＝83.3背景px（正面は88.4px）。

| 景物 | 表示尺度 | 実表示の目安 |
| --- | --- | --- |
| 両家 | 0.30 | 戸口約93px。家同士の戸口高は統一 |
| 木 | 0.33 | 根元〜上端約323px。葉は通行判定に含めない |
| 灯籠・桶・壺の組 | 0.065 | 灯籠本体約44px、桶・壺はそれ以下 |
| 竹垣 | 0.085 | 柱の高さ約38px、足元植物を含む全景約46px |
| 岩・草花 | 0.065 | 岩本体約36px、植物込み約46px |
| 橋 | 0.22 | 川を跨ぐ幅を維持、歩行床幅433px・奥行約51px |

一枚にまとめられた灯籠・桶・壺・草花は素材内部の比率を維持する。別々の高さを要求する場合は独立素材化が必要。地面に描かれた石・草の比率は今回変更していない。

## 接地からデータを作る

`footprintPx` / `surfacePx` は**原画を見て手で指定した接地・床の範囲**。alphaから自動作成しない。実行時は描画と同じanchor・scaleを使い、X=(sourceX-anchorX)×scale/ppm、Z=(sourceY-anchorY)×scale/(ppm×sin40°)へ変換する。配置移動・拡縮の際も同じ元データから判定が追従し、別々の概算値を重ねない。旧形式のworld footprint/surfaceも読み込めるが、同一素材に両形式を併記しない。

家は壁の地面側をy940、竹垣は柱の根元付近、木は幹・根、岩は石の底部、橋は板の内側を指定。葉・屋根・透明余白・花先・影は物理占有ではない。厳密な3D復元ではなく、この配置での手動登録。

## 遮蔽の不具合

05では家の壁前端を移したが、単純な配置Z順を維持していた。そのため壁の前に到達できても、画像アンカーの奥へ入ると家が緋月を覆っていた。`sortY` を原画の接地線として別に登録し、描画順も同じ変換で決める。家の手前は緋月が手前、家の奥・木の裏は景物が手前になる。

複雑な長い壁、屋根の下を歩く構造、橋下の別歩行面は未対応。今回の家・配置を変更する場合は遮蔽を再検査する。

## 再現と検査

- `npm test`：元画素と判定の変換一致、尺度追従、手前の緋月と家の描画順、不正データ、各景物の占有、両玄関・橋・対岸への到達。実機の年齢感・美術承認の代用ではない。
- `node tools/render-scene-qa.mjs`：任意の@napi-rs/canvas環境で同じ実レンダラーによる玄関・全景・判定重ね合わせ。今回の目視検査に使用。
- `tools/map-browser-smoke.mjs`：縦横・Chromium/WebKitで玄関へ移動後、戸口上に緋月の髪が実際に描画されていることを画素検査し、スクリーンショットを保存。05で見逃した遮蔽を再発検査する。
- 配置revision=6。05の保存配置は引き継がない。モジュール・CSS参照はscene-alignment-6。

iPhone Safari実機をこちらでは操作できないため、実機合格とは扱わない。公開前後のクラウド操作・描画・配信データを区別する。
