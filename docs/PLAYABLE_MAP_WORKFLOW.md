# 歩けるレイヤーマップの制作・引継ぎ手順

## まず別チャットで読むもの

`AGENTS.md` → `skills/build-layered-rpg-maps/SKILL.md` → `docs/CURRENT_ARCHITECTURE.md` → `maps/village/map.json`。`old/` は今回の指示なしに開かない。キャラは `assets/characters/hizuki-v35/character.json` と通常版PNGを確認する。

## 実際に使う順序

1. 出発点から家・木の前後・橋の両岸・出口へ行く経路を決める。今回は小さな屋外区画に絞った。
2. 世界単位・投影・画像px・尺度・足元を記録する。俯角40°と100px/mは今回の設定で、別マップへの一律制約ではない。
3. 地面は景物の下も描く。家・木・橋は独立RGBAで用意し、同じ視点・光・彩度にそろえる。一枚の村絵を切り抜いて量産しない。
4. 素材の画像寸法・地面原点・表示倍率を台帳に登録し、幹／建物の物理占有と画像を別々に持つ。透明ピクセルのRGBに色があっても、alpha=0なら表示されない。実際の背景に合成して縁を確認する。
5. 川の両岸を正の歩行面にし、橋の床だけを追加する。橋の移動／削除時に歩行面も動くことを確認する。
6. 家と木を実キャラと同じ描画処理で合成する。足元を基準に手前／裏を切り替え、屋根や壁で不足する場合は画像部品と遮蔽を分ける。判定を不自然に広げて隠さない。
7. 「配置・検査」で足元・占有・歩行面を確認し、景物を動かす。表示と判定を別座標で更新しない。JSONを書き出して読み直し、同じ配置に戻るか確認する。
8. 縦横、画面端、追従、タップ、スティック、取消・画面切替、再読込を確認する。キャラ完成前の立ち姿移動と、完成歩行アニメ検査は別。
9. 素材の出典・生成条件・JSON・検査コード・結果・未確認事項を保存する。公開ビルドに旧コードやアーカイブを混ぜない。

## 再現コマンド

```bash
npm test
node tools/verify-archive.mjs
python skills/build-layered-rpg-maps/scripts/check_map_assets.py maps/village/map.json
npm run build
```

HTTPサーバーで `dist/` を配信して `index.html` を開く。file://直開きはJSON取得に使わない。マップの公開URLとソースは分け、別チャットはレポジトリを取得して上記手順で再現する。

## 今回の生成条件

前回の淡彩村を画風参照にし、内蔵画像生成で空の地面・単独の家・単独の木・平たい橋の床を別々に作成。地面は小石と草を含み、右側に連続した川、左側に配置できる空間を確保。家と木は影や地面を抱え込まない透過素材、橋はキャラを隠す高い欄干のない床を指定した。実ファイルの元名・SHAは `maps/village/asset-provenance.json`。

## つまずいた箇所と今回の対策

| 症状 | 対策 |
| --- | --- |
| 一枚絵の切り分けで下地が欠ける | 初めから空の地面と独立物体を用意 |
| 葉や屋根の画像範囲が通行不可になる | 地面原点と小さい物理占有を別登録 |
| 橋で川全体を通れてしまう | 床の歩行面だけを面の和集合へ追加 |
| 画像が変わるとキャラの足元がずれる | 共通セル・尺度・アンカーをマニフェスト化 |
| JSON読込後にキャラが消える | プレイヤーにはX/Zだけをコピー、描画用IDを上書きさせない |
| 空の歩行配列で停止する | 置換用キャラ定義を読込時に検証。未制作は省略 |
| 透過なのに周りに色が見えると誤判定 | RGB単独表示ではなく実RGBA合成とalpha値で確認 |
| 旧実装が公開に混ざる | ビルドを現行4ディレクトリの許可リストに限定 |

## 完了段階

今回の段階は屋外の歩行試作。部屋・隣接マップ、NPC、最終キャラ素材は未制作。クラウドのブラウザ検査とiPhone Safari実機合格を混同しない。採用指示が出た通常版緋月を使い、隔離したジグザグ陰影を現行素材へ戻さない。

## 別環境のブラウザ検査

Node 20以上。`npm install --no-save --package-lock=false playwright@1.51.1` と `npx playwright install --with-deps chromium webkit` を実行し、`dist/` を127.0.0.1:8765でHTTP配信して `node tools/map-browser-smoke.mjs` を実行する。別URLでは `MAP_TEST_URL` を設定する。生成画像を再生成しなくても、同梱された画像とJSONで表示を再現できる。

書き出すJSONはマップ配置と出発点で、現在のキャラ位置は含まない。現在位置は端末localStorageに別保存される。別環境へはJSON単体ではなく画像・キャラ設定・ランタイムも取得する。読込画像の相対パスは `maps/village/map.json` の場所を基準とする。

画像生成自体は非決定的で、プロンプトだけで同じ画素を再現できるとは保証しない。使用した内蔵生成器はモデル版を返さないため版は未取得と記録し、保存PNGのSHAと実ファイルを再現の正本にする。
