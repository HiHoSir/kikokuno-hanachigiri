# 鬼哭の花契り — ブロック式家づくりエディタ 設計仕様 v1.0

> **目的**：この文書だけを別のAI・開発環境へ渡し、iPhone Safariから使える「3Dブロック式の家づくりツール」を試作・評価できること。
>
> **状態**：検証用の設計案。実装・公開・品質確認を保証するものではない。
>
> **最初の成果物**：日本家屋を基本ブロックで組み立て、回転・削除・材質変更・保存・再読込できる、独立したブラウザエディタ。

## 1. 背景とねらい

従来の「完成画像を解析して建物の位置・接地・当たり判定を推測する」方式では、縮尺・遮蔽・通行のずれが発生しやすかった。新方式では、**3D構造を正本**とし、テクスチャや2D描画はそこから派生させる。

基本工程：

```text
ブロックで3D構造作成
    ↓
必要な箇所を数値調整・専用パーツで補正
    ↓
材質／テクスチャ適用
    ↓
建物テンプレートとして保存
    ├─ 編集用：構造JSON
    ├─ 表示用：3Dモデル（将来はGLB）または固定カメラで出力した透過PNG
    └─ ゲーム用：衝突形状／歩行面／入口・出現位置データ
```

目標はマインクラフトの外観の再現ではない。**ブロックを制作上の共通構造として利用し、完成時には淡彩・水墨画調の和風RPG背景にもできること**。

## 2. 初期スコープ

### v1で実装すること（MVP）

1. 立方体、横ハーフ、縦ハーフ、階段、斜面（屋根）、薄板、柱を配置できる。
2. グリッドに吸着して置く。重なりを禁止または警告する。
3. 部品の方向を90°刻みで変更できる。選択・削除・複製・Undo/Redoに対応する。
4. 選択部品の材質を「木／白壁／瓦／石／土／草」などの仮パレットから変更できる。
5. 俯瞰、正面、側面、上面で確認できる。俯瞰角は固定しない。
6. ワンタップで小さな日本家屋のサンプルを読み込める。柱・壁・屋根・入口を別部品として保持する。
7. 構造JSONの書出し・読込みに対応する。読込みエラー時は作業内容を保持する。
8. iPhone Safariでタップ操作できる。ページ再読込後にローカル保存を復元できる。
9. エディタとゲーム本体は独立させ、既存ゲームの表示・データを変更しない。

### v1では必須としないこと

- 建物の自動生成AI、自然言語からの自動配置。
- 手描きの高品質テクスチャ自動生成。
- 複雑な屋根の曲線、瓦1枚ずつの生成。
- GLB書出し、最終的なゲーム本体への実装、室内外の移動処理。
- 本格的な地形エディタ、リアルタイム共同編集。

これらは拡張対象。最初は**家1軒の形状と操作精度を証明する**。

## 3. 座標・寸法規則

- 世界座標は **X=左右、Y=高さ、Z=奥行き**。床はXZ平面。
- 建物正面は初期状態で **+Z方向**。Xの正方向を右とする。
- 世界単位はメートル。**基本立方体1個 = 1m × 1m × 1m** を初期値とする（最終ゲーム規格とは限らない）。
- グリッド吸着単位は0.5m、細部用に0.25mへ切替可能。
- 部品の位置は「部品の中心」ではなく、**外接直方体の最小隅を基準にしたローカル位置**で持つか、中心基準ならその旨を全パーツで統一する。v1は中心位置 (`position`) を採用する。
- 回転は原則としてY軸周りの `0 / 90 / 180 / 270` 度。カメラ回転とは独立。
- 描画用のPNG画素サイズを世界座標の単位として扱わない。
- 登場キャラクターの見た目との縮尺比較は採用済み実素材で行い、家や戸口をキャラに合わせる。仮の高さを承認値とみなさない。
- カメラ俯角40°は**固定規格ではない**。評価時には複数角度を切り替えられるようにする。

## 4. 基本ブロック・パーツ体系

| `type` | 初期外形 (X×Y×Z、m) | 用途 | 注意 |
|---|---:|---|---|
| `cube` | 1×1×1 | 土台、壁、立体構造 | 基本単位 |
| `slab_horizontal` | 1×0.5×1 | 床、段差、低い土台 | 上下配置可能 |
| `slab_vertical` | 0.5×1×1 | 薄い壁、腰壁 | 回転して向きを変更 |
| `stairs` | 1×1×1 | 玄関階段、段差 | 外形は階段の段形状。単純な箱にしない |
| `wedge` | 1×1×1 | 勾配屋根、傾斜面 | 直方体を斜めに切った三角柱形状 |
| `panel` | 1×0.125×1 | 床板、庇、屋根板 | 厚みは可変 |
| `post` | 0.25×1×0.25 | 柱・柵 | 高さ可変 |
| `beam` | 1×0.25×0.25 | 梁・軒下 | 長さ可変 |
| `door_opening` | 1×2×0.25 | 出入口の位置・空間 | 入口の当たり判定を壁扱いにしない |
| `window_panel` | 1×1×0.125 | 窓・障子 | 当初は装飾として扱う |
| `terrain_slope` | 1×0.5×1 | 坂・土手 | 家エディタでは後回し可 |
| `terrain_top` | 1×0.25×1 | 地面、草地 | 家の足元確認用 |

任意寸法へのスケールを許すが、編集・検査上は部品単位の形状を保ち、画面に描いた見かけの大きさだけを変えない。

### 日本家屋専用の複合部品（v1以降）

- 柱＋壁1スパン、窓付き壁、戸口付き壁、軒・庇、切妻屋根の左右、棟、屋根端部。
- **複合部品は編集可能な基本ブロックの集合**として展開できる。
- 建物テンプレートには部品構成だけでなく、材質、玄関座標、地面との接触範囲も格納する。
- 曲面や複雑な端部は後段で専用メッシュに置き換えてよい。すべてを立方体だけで表現することを強制しない。

## 5. 描画と材質

1. 編集時は半透明ではない基本材質の3D表示を行い、パーツ選択時はハイライトする。
2. 最初の材質ID：`wood`（木）、`plaster`（漆喰）、`tile`（瓦）、`stone`（石）、`earth`（土）、`grass`（草）、`darkwood`（濃い木）。
3. 材質はパーツごとにIDで参照し、色・質感は別のマテリアル定義に格納する。**後から同じ形状へテクスチャを一括適用**できるようにする。
4. ブロック隙間の目立ちや、屋根の強い段差は、面結合・屋根専用パーツ・テクスチャ仕上げで解消する。
5. テクスチャのUVは物理的な面に従わせ、木目は柱・梁の長軸に沿わせる。
6. 完成建物をGLB等へ出力する場合も、**編集可能な構造JSONを正本として残す**。

## 6. iPhone Safari操作仕様

- 上部：常に編集対象（例：家A）・保存状態を表示。
- 中央：3Dプレビュー。スマホ縦画面でも主要な建物が見える。
- 下部固定：`配置 / 選択 / 削除 / 視点` のモード、部品種・材質・向き・高さ層、`Undo / Redo`。
- 配置モード：設置面をタップしてグリッド吸着で設置。設置前に半透明プレビューを表示する。
- 選択モード：パーツをタップすると選択し、削除・回転・材質変更・複製が可能。
- 視点モード：1本指ドラッグで回転、ピンチでズーム、2本指ドラッグでパン。
- 操作が衝突しないよう「視点」と「配置」を明確に切り替える。配置中の意図しないカメラ回転は禁止。
- `俯瞰 / 正面 / 側面 / 上面` ボタンを用意する。
- 高さ層を選ぶと、その層に設置する。上層・下層は必要に応じて半透明で表示できる。
- タップ対象は約44 CSS px以上。iPhoneのセーフエリア (`env(safe-area-inset-bottom)`) を考慮。
- 文字入力やファイル選択時、選択パーツや編集状態が消えないこと。
- オフライン再読込に備え、作業内容をブラウザのローカルストレージ等へ保存する。

## 7. 保存データ仕様（ドラフト v1）

**構造JSONを単独で持ち運べること**を優先。画像・3Dバイナリに依存しない。

```json
{
  "schema": "hanachigiri-block-house-v1",
  "unit": "metre",
  "grid": 0.5,
  "origin": [0, 0, 0],
  "front": "+Z",
  "name": "sample-japanese-house",
  "materials": {
    "wood": { "color": "#795b43" },
    "plaster": { "color": "#e4dbc5" },
    "tile": { "color": "#505b68" },
    "stone": { "color": "#92928d" }
  },
  "parts": [
    {
      "id": "foundation-01",
      "type": "slab_horizontal",
      "position": [0, 0.25, 0],
      "size": [6, 0.5, 5],
      "rotationY": 0,
      "material": "stone",
      "role": "solid"
    },
    {
      "id": "front-post-01",
      "type": "post",
      "position": [-2.75, 1.75, 2.25],
      "size": [0.25, 2.5, 0.25],
      "rotationY": 0,
      "material": "wood",
      "role": "solid"
    },
    {
      "id": "roof-left-01",
      "type": "wedge",
      "position": [-1.5, 3.5, 0],
      "size": [3.5, 1.0, 5.5],
      "rotationY": 0,
      "material": "tile",
      "role": "decorative"
    }
  ],
  "entrances": [
    {
      "id": "front-door",
      "position": [0, 0.5, 2.5],
      "facing": "+Z",
      "width": 1.0,
      "clearanceHeight": 2.0
    }
  ]
}
```

### データ契約

- `position` は部品の**ローカル中心座標**。`size` は回転前のローカル寸法。
- `rotationY` は度数で `0/90/180/270`。この角度に応じてX/Z方向の占有を変換する。
- `type=wedge` 等の形状は必ず共通の頂点生成関数に定義する（表示と当たり判定で別の形状を作らない）。
- `role` は初期案として `solid`（障害物）、`walkable`（通行面）、`decorative`（表示のみ）、`trigger`（入口等）を用いる。
- 建物の玄関は入口データと壁の欠き込み／空隙で表現し、単なる透明テクスチャで通路を作らない。
- 書出しにはパーツID・順序・寸法・材質を保存する。読込後に再書出しした構造は意味的に同一となること。
- 未知スキーマ・不正座標・負寸法・重複ID・不正マテリアル参照を検出し、現在の編集内容を破壊しない。

## 8. サンプル家屋の最低仕様

**試作用の仮寸法（承認済みゲーム寸法ではない）**：基礎6m×5m、壁高2.5m前後、切妻屋根、玄関幅1m、高さ2m程度。

- 土台：横ハーフ／石材。
- 壁：縦ハーフ＋漆喰。
- 柱：木材の縦材。
- 屋根：左右の斜面＋棟。屋根は壁より外へ張り出す。
- 入口：正面中央。壁とぶつからず入れる隙間をモデル上に確保する。
- 玄関段：階段ブロック。
- サンプル読み込み後も、屋根材の変更、屋根の片側削除、柱の移動が可能なこと。

## 9. 将来のゲーム連携

エディタが書き出す構造JSONから、次を派生させる。

- `render`: メッシュ・マテリアル → GLB、または任意カメラからレンダリングしたRGBAレイヤー。
- `collision`: `solid` 部品の占有形状を合成した衝突データ。屋根など地上移動に不要なものを無条件に障害物としない。
- `walk_surfaces`: 床・階段・橋・地面など、歩行可能な高さ付き面。高低差間の接続条件を記録。
- `entrances`: 入口の位置・幅・向き・遷移先。
- `occlusion`: 2D化する場合は屋根・壁の前景マスクや深度分割を生成。

**注意**：3Dメッシュがあれば必ず正しい歩行判定が自動作成できるわけではない。部品の意味付けと接続条件を検証する必要がある。

`鬼哭の花契り` プロジェクトへの導入時は、現在の `AGENTS.md`、`skills/build-layered-rpg-maps/SKILL.md`、`docs/MAP_ART_RULES.md`、`docs/MAP_ASSET_CONTRACT.md` を確認する。既存のCanvas2Dゲームや既存マップを、実験だけで書き換えない。正式な3D→2D化・WebGL採用は別途比較する。

## 10. 推奨実装構成（無料）

- **HTML / CSS / JavaScript** のブラウザ単体ツール。GitHub Pagesで無料公開。
- 表示はThree.js等の無料オープンソース3Dライブラリで構わない。利用時は版を固定し、ネットワーク依存と再配布条件を記録する。
- JSON生成・検証はライブラリ依存を最小化した純粋関数にする。
- ファイル書出しはブラウザのBlobとダウンロード操作、読込は`input[type=file]`で対応。
- バックエンド／有料3Dサービス／外部AI APIは不要。
- モデルの3D出力（GLB等）はv1以降に追加してよい。初回はJSON保存を優先する。

推奨ファイル分割例：

```text
house-editor.html
house-editor/
  model.js         # ブロック型・形状生成・バリデーション
  editor.js        # 選択、配置、移動、回転、Undo/Redo
  render.js        # 3D表示、カメラ、タップ判定
  io.js            # JSON書出し／読込／ローカル保存
  samples.js       # 最小の日本家屋テンプレート
  styles.css
  tests/           # 座標・回転・データ往復・形状テスト
```

シンプルな試作では1つのHTMLにまとめてもよい。ただしデータモデルと描画操作は分離して設計する。

## 11. 受入テスト（QA）

| ID | 検査 | 合格条件 |
|---|---|---|
| H-01 | サンプル家屋 | 柱・壁・屋根・玄関が独立して編集できる |
| H-02 | 立方体配置 | X/Y/Zが指定グリッドに吸着し、JSONと一致 |
| H-03 | 縦ハーフ | 90°回転で厚み方向が正しく変わる |
| H-04 | 階段・斜面 | 外形が本当に段形・斜面で、ただの箱ではない |
| H-05 | 材質変更 | 1パーツと同一材質の一括変更を区別できる |
| H-06 | 入口 | 正面壁に物理的な開口があり、不可視の壁で塞がない |
| H-07 | Undo/Redo | 配置・削除・回転・材質変更を正しく戻せる |
| H-08 | JSON往復 | 保存→再読込後、寸法・位置・回転・材質・入口が維持される |
| H-09 | 不正ファイル | 読込エラーでも現在の作品を保持する |
| H-10 | iPhone縦横 | タップ・拡大縮小・パーツ選択・メニュー操作が可能 |
| H-11 | 画角変更 | カメラ操作で建物の実寸法が変わらない |
| H-12 | 既存ゲーム保護 | ゲーム本体のマップ・キャラ・既存セーブを変更しない |
| H-13 | ブロック衝突 | 不正な重なりが分かり、例外的な重ね配置も明示できる |
| H-14 | 実機 | GitHub Pagesの公開版をiPhone Safariで動作確認する（クラウドWebKit検査と区別） |

**報告には**「実装済み」「テスト済み」「iPhone実機確認済み」「未実装」を明確に分ける。画像だけで操作・精度・実機性能を合格にしない。

## 12. 他のAIに渡す実装依頼テンプレート

以下をそのままコピーできる。

> 添付の「ブロック式家づくりエディタ 設計仕様 v1.0」に基づいて、iPhone Safariで使える独立したWebエディタを実装してください。まずは家1軒をブロックから組み立てるMVPに限定し、立方体／横ハーフ／縦ハーフ／階段／斜面／薄板／柱、配置・選択・回転・削除・材質切替、サンプル日本家屋、Undo/Redo、構造JSON保存・再読込を必須にしてください。固定の40°カメラへ戻さないでください。ブラウザで本当に操作できることを検査し、データの座標・サイズ・当たり判定候補を見た目と独立して検証できるようにしてください。外部有料サービスは利用しません。完了時はテスト結果、操作方法、未対応事項、公開URLを提示してください。既存ゲームへの無断変更はしないでください。

**判定基準**：「美しい完成画像が得られたか」ではなく、**同じ構造データから、編集可能な家が再現され、見た目と物理配置を別々に検証できたか**を最初の合格条件とする。
