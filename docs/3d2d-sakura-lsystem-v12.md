## 構成

- 太幹・7本の主枝：既存の桜花に接続する位置を維持する3D骨格。幹は根元に向かって太くなるメッシュ。
- 自動細枝：規則 `A → F[+A][-A]` を4回展開して3Dタートルで描画。枝角25°、長さ比0.7。固定乱数で再現可能。7本の主枝の途中2箇所から開始し、計210本の細枝セグメントが追加される。
- 花の奥・中・手前：前回v11と完全に同じ3枚の2D RGBAレイヤー。花の描画位置・密度は変更しない。
- 根：前回の2Dの地表根、土、苔、下草、花びらをそのまま利用。3D露出根を復活させない。
- 当たり判定：以前と同じ幹の中心半径0.26m。足元(10.9, 7.2)、俯角40°、方位35°、画面・経路・橋・川・建物は変えない。
- 緋月：デモは本編 `src/map/renderer.js` の `loadCharacter()`、`src/map/motion.js` の `MotionPlayer`、`src/map/character-visual.js` の `drawCharacterFrame()` を直接import。独自の旧モーションを内蔵しない。

## 再現方法

Python 3、Pillow、numpy、trimesh、numba。ソース一式（`source/`）、v11バックアップ (`baseline/`)、atlas (`assets/texture-atlas.png`) が同梱。

```bash
cd source
python build_sakura_lsystem_v12.py --iterations 4 --angle 25 --ratio .70
python make_html_v12.py
python test_sakura_v12.py
python test_browser_v12.py  # Playwright Chromium が必要。QA用のモック画像を用いる
```

`build_sakura_lsystem_v12.py` で枝角・枝の長さ比・反復を変更できる。出力は `assets/sakura_trunk.glb`、`assets/sakura_trunk.png`、`assets/sakura_hybrid.png`。別パラメータで再生成する際は出力が枠に収まるか検査すること。

## 評価・限界

幹・枝の**生成規則の自動化**を検証する技術試作。花の奥に隠れる細枝も多く、完成した桜を花付きで表示するとv11との差は控えめ。`枝だけ表示`で構造の違いを確認できるが、これをもって樹形の最終美術品質が完成したとはしない。

現状の根元の2D表現の好みについては未承認。根元の改良と生成樹形の採否は別々に判断する。
