# 花契り・淡彩レイヤーマップ制作ルール

地面・独立した景物・実キャラ・歩行データを分け、同じ描画処理で組み合わせて検査する。完成イラストの自動レイヤー分解を量産の前提にしない。

## 適用範囲と正本

- 対象は続編『鬼哭の花契り』、`HiHoSir/kikokuno-hanachigiri`。『鬼哭の花結び』の `yaksha-hanamusubi` と混同しない。
- 着手前に対象ブランチの `AGENTS.md`、`docs/MAP_ART_RULES.md`、`docs/LEGACY_INFORMATION.md`、`docs/CURRENT_ARCHITECTURE.md`、`docs/PLAYABLE_MAP_WORKFLOW.md`、`docs/ASSET_POLICY.md` と実素材を読む。存在しない資料は未取得と記す。
- `old/` は『花結び』由来の旧情報。通常の新作制作で正本として読み込まない。再利用依頼がある場合だけ出典・採用範囲を確認し、新作用資料へ独立して記録する。旧資料中の作品名や「確定・実装」は新作の承認・実装を意味しない。
- 旧2Dキャラ×3D背景の検証は `old/` に隔離済み。現行の初回歩行試作は独立画像を使うCanvas2Dで、契約と検査状況は CURRENT_ARCHITECTURE / PLAYABLE_MAP_WORKFLOW を正本にする。
- 既存の32pxグリッド、28pxキャラ、4方向移動、最近傍拡縮、固定マップ寸法を新作へ自動適用しない。画像px・世界座標・画面表示サイズを分ける。既存コードの寸法を流用するときは、その根拠と変換を明示する。
- 読み取れた利用者の最新指定を優先する。提案・承認・実装・実機合格を区別する。既に依頼された範囲の通常作業は重ねて許可を求めず進める。

## 初期制作基準

| 項目 | 初期値・扱い |
| --- | --- |
| 美術 | 淡彩画調の和風背景＋輪郭と色面が読み取れるセル画調の緋月。エターニアを目標にしたセミSDと空間の読みやすさを重視 |
| カメラ | 平行投影、水平0°・真上90°で俯角40°。40°は初期提案で、最終採用値は比較または明示指定で確定 |
| 方位 | 俯角と別にカメラ方位・キャラ向きを記録。方向別素材は同じカメラでモデルを回す |
| 緋月 | 利用者が指定した実モデル／実レンダーを基準にする。版・出典・撮影条件を記録 |
| 大きさ | 実キャラの画面上の高さを物差しに入口・家・木を決める。元画像解像度を一律固定しない |
| 光・質感 | 背景とキャラの光源方向、影の柔らかさ、輪郭、彩度をそろえる。光沢を抑えたトゥーン表現を初期案にする |
| 操作・費用 | iPhone Safari優先、原則無料。未確認の外部サービス機能や有料機能を必須工程にしない |

カメラ比較を頼まれたら同じモデル・姿勢・尺度・光で30°／40°／50°を並べる。画像生成への角度指定だけを正確な投影の証拠にしない。絵を傾けて俯角の違いを代用しない。

## 制作順序

1. **現物を特定する。** 最新指定のモデル、採用原画、既存のマップ描画・入力・衝突・保存の方式を調べる。以前の版番号だけでモデルを選ばない。実モデルがなければ地形・配置の試作を進め、キャラ適合検査を未確認に残す。
2. **納品段階を決める。** 完成像のイメージ、素材セット、歩行試作、本番採用のどこまで依頼されたかを記録する。イメージだけの依頼で実装まで勝手に進めない。
3. **制作契約を記録する。** [素材・配置・検査契約](MAP_ASSET_CONTRACT.md)を読み、カメラ、尺度、原点、足元アンカー、光、ファイル、出入口、歩行面、判定、描画順を記す。既存契約があれば拡張し、別規格を乱立させない。
4. **経路から小区画を組む。** 家2軒程度・木・岩・道・小川・橋を検証用の目安にする。開始地点→木の前後→玄関→橋の両岸→出口の経路を先に確保する。通路幅はキャラ判定と操作余裕から決め、32pxや1セルに固定しない。依頼にない要素は追加しない。
5. **不足する独立素材を作る。** 地面／道／岸／水、家、木、岩、小物を別ソースにする。家一軒や木一本を大きな透過素材にしてよい。採用素材を再利用し、同じ視点・尺度・光・画風の参照を生成へ渡す。地面は景物で隠れる箇所も用意する。
6. **透過と接続を検査する。** 景物は真正RGBAで保存する。市松・白縁・草地を抱えた輪郭・欠け・誤った透過穴を確認する。接続する道・川・岸・橋は共有端点と接続形状をそろえる。淡彩素材を機械的にドット絵化せず、縮小は実表示で選ぶ。
7. **実際に合成する。** 仮図形は経路確認用と明示する。美術の合否には緋月の実レンダーを使い、足元アンカーと接触影を合わせる。モデルの顔・体型・衣装を背景に合わせて勝手に変えず、まず背景の密度・輪郭・色を調整する。接地影を素材とゲームの両方に重ねない。
8. **歩行と遮蔽を検査する。** 地面・接地影、景物とキャラの深度順、前景、効果を分ける。単純な景物は同じ歩行面の足元深度で並べる。長い壁・大きい家・橋・階段は部品分割、明示遮蔽、歩行面別の判定を使う。画像の下端・アルファ・影を衝突範囲にしない。
9. **採用と引継ぎを残す。** 原画／元モデル、派生PNG、制作契約、素材台帳、配置、判定、出入口、生成条件、検査証拠、未確認事項を関連付ける。保存・公開は利用可能な正式手順に従い、未公開や実機未確認を明記する。

## 一枚絵を使う場合

- 通常マップは独立素材の合成を基本にする。特別な景色には一枚絵方式を検討できる。
- 一枚背景を表示→キャラ→必要な木や屋根だけを元画像と同位置で重ねる方式では、正確な輪郭マスクと前後切替の範囲を記録する。画像全体の再生成は不要。元絵から見えない歩行面が必要なら、その箇所の地面補完が必要。
- 移動できる独立物体へ切り出す場合は、物体全体と隠れていた背景を別々に復元する。小さく切った合成図を独立素材と呼ばない。
- マスクの縁で不要な地面までキャラを隠さないか、元背景の物体が二重に残らないかを検査する。自動分離・切り抜き成功を実物なしで保証しない。

## 合格基準と報告

- **素材セット**：視点・光・尺度が一致し、独立RGBAと必要データがそろい、実表示で輪郭・接地が成立する。
- **歩行試作**：木の手前／裏／左右、家の角と出入口、橋の両方向と岸、画面端で前後関係と通行が成立する。橋下を歩かせる場合は橋上と別の歩行面として検査する。
- **実キャラ適合**：指定版の緋月で静止・歩行・走行、向きの切替、背景との密度差、足滑りを検査する。存在しないモーションは対象外と記す。
- **本番採用**：実配信データをiPhone Safariで検査し、タッチ移動・縦横表示・追従・再読込・マップ遷移・配置保存往復を確認する。未実装項目は未実装、端末を操作していなければ実機未確認とする。
- 実装変更には既存の適切なテストを実行する。静止画だけで動的遮蔽・操作・性能を合格にしない。新規マップの結果に過去の別マップの合格を流用しない。
- 報告は「作ったもの」「使用素材・モデルと条件」「確認できたこと」「未確認・次の検証」を短く示す。

## よくある誤り

| 誤り | 修正 |
| --- | --- |
| 旧作の32px規則を仮に固定する | 現行契約か実キャラ尺度から決め、未定を明記 |
| 美しい一枚絵をレイヤー素材完成とする | 独立ファイル・配置・判定・実合成の証拠で区別 |
| 実モデルの代わりに生成キャラで相性合格とする | 生成キャラはイメージ専用、指定実レンダーで再確認 |
| 全景物を一律Yソートすれば橋も解決とする | 歩行面、高さ、遮蔽部品を分ける |
| 透過画像の見える範囲を通行不可にする | 足元の物理占有だけを明示登録 |
| 一枚絵分解が難しいので無料未検証サービスを連鎖させる | 小区画と独立素材に戻り、実行可能な工程を選ぶ |
