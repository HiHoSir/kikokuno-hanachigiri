# 素材・配置・検査契約

これは制作データの意味をそろえるための契約であり、既存ゲームがこのJSONを読めるという仕様ではない。接続先の実スキーマがあれば変換を明示して使う。

## 制作票

最初の区画で以下を記録し、別の素材・区画でも引き継ぐ。未決の値には `provisional`、承認した値には `approved` を付ける。

| 分類 | 必須記録 |
| --- | --- |
| 対象 | 作品、レポジトリ、作業ブランチ、マップID、用途、納品段階 |
| 出典 | 元ファイルの場所・版・ハッシュ、既存素材の採用状態、参照画像の役割 |
| 撮影 | 投影方式、俯角の定義と値、方位、画角範囲／ortho scale、モデル向き、原点、トリミング |
| 尺度 | 世界単位、基準キャラ身長、画面上のキャラ高、画像pxから世界単位への倍率、表示倍率 |
| 美術 | 画風参照、パレット、輪郭、明暗段階、光源の方向と座標系、影の色と柔らかさ、縮小フィルター |
| 出力 | 原画・モデル、透過PNG、影、素材台帳、配置・判定・入口データ、検査記録の保存先 |

## カメラと座標

- ワールドは `X/Z` が地面、`Y` が高さ。マップ画像のピクセルを世界座標として暗黙に流用しない。
- 俯角は水平0°、真上90°。40°は初期値であってエターニア実機を測定した値ではない。キャラと背景で同じ値を使う。
- カメラ方位0°を「+Z側から原点を見る」と定義する場合、距離D・俯角θで位置は `(0, D sinθ, D cosθ)`、注視点は原点、上方向は+Y。方位を変える場合は規則を明記する。
- この方位0°、平行投影、倍率Sなら、画面右は `S·X`、画面下は `S·(Z sinθ − Y cosθ)`。これにカメラ中心と画面中心のオフセットを加える。他方位には同じ式をそのまま適用しない。
- キャラの足元アンカーは共通のモデル原点から投影する。各フレームの不透明範囲で中央寄せし直さない。走行の上下動や足離れをトリミングで打ち消さない。
- 背景生成は厳密なカメラを保証しない。必要なら同条件の3Dブロックアウトを視点参照に使う。ブロックアウトを最終美術に置き換えたと報告しない。

## 素材台帳

素材ごとに次を持たせる。

- `id`, `source`, `source_version`, `image`, `image_size_px`, `status`。
- `anchor_px`：画像左上からの足元原点。影・木の葉・透過余白の下端ではない。
- `world_size`：画像の表示幅・高さ。リサイズ時は縦横比と原画を保つ。
- `footprint`：アンカー基準の地面上の衝突多角形。画像アルファと別に定義する。
- `render_parts`：各部の画像、ローカル位置、描画区分、遮蔽／深度の基準。
- `shadow`：別画像または実行時生成のどちらか。色・濃さと重複防止を記す。
- `entrances`：接近範囲、侵入トリガー、移動先・出現位置・向き・戻り先。自動出入り口は復帰直後の再発火も検査する。

### 小さな素材例（寸法は例示で、採用規格ではない）

```json
{
  "id": "tree_a",
  "source": "sources/tree_a.png",
  "source_version": "trial-01",
  "image": "sprites/tree_a.png",
  "image_size_px": [384, 512],
  "status": "trial",
  "anchor_px": [192, 468],
  "world_size": [2.0, 2.6666667],
  "footprint": [[-0.18, -0.13], [0.18, -0.13], [0.18, 0.13], [-0.18, 0.13]],
  "render_parts": [{"image": "sprites/tree_a.png", "layer": "depth_sorted", "sort_origin": "anchor"}],
  "shadow": {"mode": "runtime", "source_has_ground_shadow": false},
  "entrances": []
}
```

上のファイル名は未作成の例。実ファイルの存在・寸法・アンカー・出典を確認してから素材台帳へ登録する。

## 配置・歩行面・描画

- マップは `map_id`, `schema_version`, `camera_profile`, `style_profile`, `bounds`, `ground`, `instances`, `walk_surfaces`, `colliders`, `entrances`, `spawn_points` を区別する。画像ファイルとデータをIDで結び、参照切れを検査する。
- インスタンスは素材ID、ワールド位置、表示尺度、歩行面ID、必要な深度補正を持つ。採用前にミラーで光源や建物の向きを変えないか確認する。
- 描画区分は **地面 → 地面装飾／接地影 → 景物とキャラ → 明示的な前景 → 効果／UI** を初期案にする。3Dレンダラーでは深度処理との対応を定義する。
- 単純な木とキャラは、同じ歩行面の接地点を同じルールで並べる。同値時の順序を安定させ、点滅や切替の振動を防ぐ。単純な画面Yだけを異なる高さへ適用しない。
- 長い壁・家の側面・回り込める景物は一つのアンカーだけで解決しない。部品分割、遮蔽マスク、または接続先の3D深度を選び、実際の交差位置で検査する。
- 橋は床の歩行多角形と接続する岸を登録する。欄干は床と分けてキャラを適切に隠す。川全体の判定や他の衝突を解除しない。
- 橋下・高台・階段がある場合は、歩行面ID・高さ・接続条件を持たせる。通常の地面と別層として通行を判定し、橋の削除後に存在しない床を歩けないか確認する。
- 水・波紋・風・霧は必要に応じて別素材／効果にする。静止画だけの素材へ動画効果が存在すると扱わない。

## 最小検証票

| 検証 | 必要な証拠 |
| --- | --- |
| 画風・尺度 | 同じ表示条件の実キャラと家・木の合成。元画像とゲーム表示の両方 |
| 透過 | 明色／暗色背景での輪郭、穴、アルファ、欠けの確認 |
| 接地 | 足元・根元・影・判定の可視化。静止と移動の両方 |
| 遮蔽 | 木の前後・左右、家の角、橋と欄干を通る実レンダラー上の動画または操作確認 |
| 到達性 | 開始→入口→橋両岸→出口。狭路・対角移動・角への接触も検査 |
| 遷移 | 入口侵入、室内出現、退出、再侵入。復帰位置の衝突とループの有無 |
| 保存 | 配置と判定・入口を保存→再読込して同じ状態になること |
| 実機 | 端末・ブラウザ・配信版、縦横表示、タッチ、ロード、追従、負荷。実測値がなければFPSを断言しない |

採用状態は `concept` / `trial` / `reviewed` / `approved`、検査結果は `pass` / `fail` / `not_checked` / `not_applicable` とし、承認とテスト結果を別項目で保持する。
