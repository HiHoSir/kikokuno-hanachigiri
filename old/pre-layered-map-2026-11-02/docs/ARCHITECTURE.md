# 2.5D RPG 実装アーキテクチャ v0.3

## 基本方針
本リポジトリは新規Web RPG用の独立した基盤。旧ゲームの固定タイル寸法・スプライト解像度・画面解像度等は継承しない。Three.jsは現時点では採用検証中。

## 現在のコード責任分離
- `src/main.js`: 起動・更新ループ・各システムの接続のみ
- `src/world.js`: 3D地形・家具・光・衝突候補の構築
- `src/character.js`: 2Dテクスチャの立体空間配置・影
- `src/camera.js`: 正投影追従カメラ
- `src/input.js`: キーボード・タッチ入力の収集
- `src/movement.js`: 画面→地面ベクトル変換、衝突判定、斜め速度補正

## 境界条件
- ゲーム位置は連続X/Z座標、Yは高さ。画像ピクセル数を世界単位に流用しない。
- キャラクターの足元を接地点とし、表示用平面と当たり判定を分ける。
- 深度バッファを利用して背景とキャラクターを遮蔽する。表現上のめり込みと物理衝突を別々にテストする。
- 画面サイズ・DPRによる描画負荷は端末ごとに変えるが、元画像の制作解像度を制限しない。

## RPG化する前に追加する境界
1. `GameState`: 主人公・フラグ・所持品等の純粋データ。表示エンジン非依存。
2. `AreaLoader`: 外部定義された地形・イベント・衝突データの非同期読み込み。
3. `EventSystem`: 操作・条件・会話・結果をデータ駆動で解決。
4. `SaveRepository`: 変更可能なセーブ形式をバージョン付きで管理。
5. `BattleSystem`: 戦闘ルールと描画を独立させる（採用方式は未決定）。
6. `AssetRegistry`: 再利用候補の出典・採用・解像度派生を追跡。

上記6点は設計候補であり実装済みと扱わない。

## 品質ゲート
`npm test`で純粋ロジックを検査する。現段階ではブラウザの視覚的な深度・タッチ・カメラ検査を自動化できていないため、合格を主張しない。
