# kikoku 64×96 / 8方向 AIドット打ちエディタ（試作）

## 目的
- kikokuの8方向イラストを**下絵**として参照し、64×96pxの実画素を人間やAIの座標修正案で直接打つ
- 画像生成・自動縮小・減色による意図しない絵柄変更はしない
- 32×32の既存エディタは保存し、解像度自由化ルールも変更しない
- オリジナルの下絵はラスタ編集画像と別レイヤーであり、エクスポートには含めない

## 仕様
- キャンバス: 64×96px／透明 RGBA
- 方向: `front`, `front_right`, `right`, `back_right`, `back`, `back_left`, `left`, `front_left`
- コマ: 方向ごとに8枚、合計64枚。編集元のコマは独立（勝手に歩行差分を生成しない）
- 下絵: `assets/characters/hizuki/8direction/*.png` を参照。既存原画はゲーム正式素材への採用を意味しない
- UI: 鉛筆・消去・塗りつぶし・スポイト・指で位置選択して1ドット打ち・Undo/Redo・色パレット・下絵濃度・フレーム再生
- PNG出力: 1コマ64×96／8方向×8コマの全アトラス512×768。アトラス列はコマ0〜7、行は上記8方向
- JSON: `kikoku-pixel-v1`、全64フレームを非可逆圧縮せず RGBA/Base64 で保持。読込とエクスポート可能
- フレーム単位とアトラス全体編集のUndoに対応

## AIドット修正
1. 現在の方向・コマを選択し、必要なら元絵の下絵濃度を調整する。
2. 左側の道具でドットを打つか、③「AIへの画素修正依頼」に言葉で指示する。
3. 「現在の画素・指示をコピー」を押し、ChatGPTへ貼り付ける。
4. AIが返した `kikoku-pixel-patch-v1` のJSONをパッチ入力欄に貼る。
5. 「変更前後を比較」で検証し、確認後に「確認して適用」を押す。

JSONパッチ例（実行時にはそのフレームの`baseHash`を指定）：

```json
{"format":"kikoku-pixel-patch-v1","direction":"front","frame":0,"width":64,"height":96,"baseHash":"<current-FNV-1a-hash>","pixels":[{"x":16,"y":20,"rgba":[24,33,54,255]}]}
```

- 対象コマと方向・解像度・元フレームのハッシュを必須検証
- RGBAの値と座標の範囲、最大1024ピクセルを検証し、差分をプレビューするまでは元画像を一切変更しない
- プレビュー後に別フレームへ切り替えたり元絵の画素が変わった場合には、適用を拒否
- 256pxを超える大きな差分には適用前の確認が必要
- ラボ内にAIをホストしているわけではない。AIとの連携はコピー/貼り付け方式

## 運用・検証
- GitHub Pages公開時は `experiments/ai-pixel-editor-64x96/index.html` でアクセスする
- この試作にはkikoku本編のゲーム画像・セーブ仕様に関係するファイルの変更はない
- GitHub Actionsのブラウザ検査で8方向、各8コマ、画素描画・Undo、JSON/PNG、AIパッチの検証を行う
- 品質評価はピクセルの実際の美術性とは別。AIが原画の造形を一発で正確に再現することは保証しない

## 追加：黒塗り原画 → Nearest シルエット下書き（2026-10-30）

人間のドット絵制作でよくあるシルエット優先の手法を採用する。

1. 8方向の原画（透明PNG）またはユーザーが指定した別の透明PNGを下絵に設定。
2. 元画像の透明度（初期しきい値128/255）で人物領域を取り出す。
3. 元画像の該当画素を単色の黒に置換する。色や模様を縮小しない。
4. 人物の外接領域を求め、縦横比を保持しつつ最大60×92pxに収める（64×96pxに透明余白を確保、足元を下寄せ）。
5. `imageSmoothingEnabled=false` の最近傍で**二値のシルエットのみ**を縮小する。
6. 現在の画素とシルエットを別々にプレビュー。原画・編集画素に自動反映しない。
7. ユーザー承認時だけ現在の1コマへ適用（Undoで復元可能）。以後、内部の色分け・目・花飾り・髪先は個別のドット打ちとAI差分編集で仕上げる。

注意点：
- **Nearestで完成絵を縮小する機能ではない。** 最初の形状の下書きだけを作る。
- 描画済みの色画像を上書きする前に明示的な確認がある。プレビュー後にフレームや画素内容が変わっていたら適用しない。
- 不透明な背景の画像はシルエット抽出を拒否する。背景透過PNGを指定すること。
- しきい値を変更したら新たに生成して比較する。小パーツや髪先の欠けは最後にドットで修正する。
- 本手法を採用した理由：以前の手打ち正面候補が原画より横に広くなりやすかったため。元絵のポーズや頭身を幾何学的な土台として優先する。
- 比較用のPythonプロトタイプは `front-passing-frame-draft.png` を使用して、原画の描画外接領域593×1358 → 40×92pxのシルエットへ変換。旧候補と幾何形状が大きく異なるため、旧候補に無理に補正を重ねない。

ブラウザ自動テストはシルエット生成、元フレーム不変、黒色1色、透明余白、明示適用、UndoでのRGBA完全復元を確認する。
